# 控制台：一个入口管理多个微信

浏览器只打开 **http://127.0.0.1:5090**，用 `.env` 里的 `WXBOT_UI_USER` / `WXBOT_UI_PASSWORD` 登录。

```
浏览器 ──► wxbot-console :5090 ──┬──► wxbot / wxbot-ubuntu-manual  (微信 1：后台 :5100、noVNC :6080)
                                ├──► wxbot-second                  (微信 2)
                                └──► wxbot-acc1、wxbot-acc2 …       (控制台「添加微信」建的)
                    (同一个 docker 网络 wxbot-net；控制台经 docker.sock 创建/启停容器)
```

- 每个微信仍是**独立容器**（自己的微信、数据卷、机器人、密钥），互不串号；控制台只是入口和管理者。
- 浏览器的请求都经控制台转发到当前选中的微信，包括扫码用的 VNC 画面（WebSocket），所以不用再记 5100/5101/6082 这些端口。
- 控制台替你登录各个微信的后台（同一套账号密码），浏览器只登录控制台一次。

## 页面

| 菜单 | 内容 |
| --- | --- |
| 总览 | 所有微信的在线状态（在线 / 待扫码 / 缺密钥 / 微信未运行 / 已停止）、机器人和发送方式，一键处理 |
| 添加微信 | 起名字 → 自动建容器 → 页面里直接扫码 → 自动读取密钥 → 完成 |
| 账号 · 概览 | 登录、密钥（刷新密钥 / 抓图片密钥）、机器人开关、发送方式与直发能力、容器（重启微信 / 重启 / 停止 / 改名 / 移除） |
| 账号 · 消息 | 会话列表 + 聊天记录（图片、语音、视频封面、引用），发消息、引用回复、@ 群成员 |
| 账号 · 扫码与桌面 | 这个微信所在容器的桌面（扫码、手动操作），「进入微信」「重启微信」按钮 |
| 账号 · 发送设置 | 界面发送 / 直发、失败回退、群里引用 / @ / 画图引用三个开关 |
| 机器人与规则 | 机器人开关、实时日志、监听 / 主动与问候 / 跟发 / 推送 / 管理员 / 上下文与画像 |
| 定时任务 | 一句话建提醒、任务列表（编辑 / 试发 / 开关）、执行记录、定时问候 |
| AI 模型与知识库 | 聊天 / 工具 / 看图 / 生图分别走哪套中转、各中转的地址和密钥、知识库 |
| 人设与画像 | 人设库、按会话指定人设、模板与批量、联系人画像、蒸馏 |
| 战斗模式 | 正在吵架的会话、吵架人设（强制红线改不掉） |
| 直发测试 | 直发文字 / 图片 / 视频 / 任意文件、引用、@、撤回上一条、直接发成语音，带直发记录 |
| 发送接口 | `/api/send` 的地址、参数说明，每个联系人一键复制 curl |
| 音色与复刻 | 音色列表（试听 / 设默认 / 编辑模型）、复刻新音色（厂商 + 模型）、语音发送形式（语音条 / 声波视频 / mp3） |
| 语音回复 | 全局：什么时候说语音、最长字数、音色；**按好友单独设置**：给某个好友（或群）指定音色、模式、开关 |
| 朋友圈 | 动态（图片、评论与回复）、发布与草稿、执行记录、自动互动设置 |
| 配置导入导出 | 打包这个容器的规则、人设、定时、知识库等（不含登录状态和任何密钥） |

页面开发说明见 `console/PAGES.md`。

### 给某个好友单独用一个音色

「语音回复」→「按好友单独设置」→「为好友单独设置」，选好友和音色。之后机器人语音回复他、你在「直发测试」里点「发成语音」、
或者调发送接口发语音但没带 `voice`，都会用这个音色。没设的好友跟随全局音色。

### 合成用哪个模型

模型跟着音色走：在「音色与复刻」里编辑音色就能改。阿里云百炼的复刻音色和模型绑定，换模型（例如 plus 复刻、flash 合成）
会用保存的录音自动在新模型上再复刻一份；其他厂商的音色不绑定模型，直接换。

### 已知限制

- 朋友圈里一部分图片是微信加密的（显示 🔒），暂时不能预览；明文图片正常显示。
- 「发送接口」页显示的是容器在 Docker 网络里的地址，从宿主机调用要换成映射出来的端口。

## 状态是怎么判断的

| 状态 | 条件 | 处理 |
| --- | --- | --- |
| 在线 | 微信已登录、数据库密钥齐全 | — |
| 待扫码 | 微信在运行但没登录 | 「扫码与桌面」扫码；刚重启微信的点「进入微信」 |
| 缺密钥 | 已登录但读不了库 | 「刷新密钥」 |
| 微信未运行 | 容器在跑、微信进程没起 | 「重启微信」 |
| 启动中 | 容器刚启动，后台还没响应 | 等几十秒 |
| 已停止 / 容器不存在 | — | 「启动」/ 移除 |

## 部署

- **新部署**：根目录 `./deploy.sh`，同时起第一个微信 `wxbot` 和控制台 `wxbot-console`（同一个镜像，控制台用 `command` 启动 `console/server.py`）。
- **已有旧容器的机器**：`docker compose -p wxbot-console -f docker/console/compose.yaml up -d`。启动时自动纳入名字是 `wxbot` / `wxbot-*` 且带后台端口的容器（跳过名字里有 `-old` 的备份），只把它们接入 `wxbot-net` 网络，不重建、不改动。
- 控制台创建的微信用 `WXBOT_ACCOUNT_IMAGE`（默认和控制台同一个镜像），容器名 `wxbot-accN`，数据卷 `wxbot-accN-home`（微信）/ `wxbot-accN-data`（密钥、人设、规则），默认直发 + 自动启动机器人。
- 注册表在控制台数据卷的 `/data/accounts.json`。

## 移除

- 控制台创建的号：删除容器；勾选「同时删除数据卷」会把登录状态、聊天记录、密钥全部清掉（不可恢复）。
- 纳入进来的旧容器：只从列表移除，不动容器，并记进忽略名单（重启控制台不会再自动纳入）；点总览的「扫描已有容器」可以重新纳入。

## 安全

- 控制台挂载了 `docker.sock`（为了创建/启停微信容器），等于能控制这台机器上的 Docker：端口默认只绑 `127.0.0.1`，远程访问请走 SSH 隧道或带认证的反向代理。
- 登录态是 HMAC 签名的 Cookie（`WXBOT_SECRET`），默认 24 小时；每个新建的微信容器有自己的 `WXBOT_SECRET`。
