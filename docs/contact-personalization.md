# 联系人画像与专属人设：本地交付说明

状态：**已实现、未部署；真实画像批量生成尚未执行**。日期：2026-09-09。
本轮仅新增联系人表达偏好、人设解析、管理页面和已有微信语音转写复用。
未重启服务、未发送微信、未调用真实模型、未修改真实联系人角色或定时任务。

## 数据与职责

- 原 `accounts/<稳定账号 ID>/profiles/<联系人>.json` 仍保存事实、scope、状态、时间和 summary；现有 `memory.select_memories()` 继续选择事实。没有复制事实库或复制聊天历史。
- 新 `accounts/<稳定账号 ID>/communication.sqlite3` 只保存通信设置、表达偏好、版本审计、证据消费 ID 和构建进度。联系人 ID 是原始稳定 username，不使用昵称；同名和改名不会改变主键。
- `settings(contact, revision, data)`：`persona_id`（null 表示动态继承）、`personalization_enabled`、`auto_update`、`preferences`。`__global__` 是后端保留的全局记录，联系人 API 不接受此 ID。
- 每项 preference 保存 `value/evidence_ids/source/confidence/updated/scope/locked`，明确消息还保存 `evidence_time`。支持 length、tone、emoji、jokes、advice、followup、address、language、dislikes；缺失和“未知”不被当作有效偏好。
- 来源结构区分 `user_explicit/admin_manual/inferred`。本版实际自动提取器只产生有原消息证据的 `user_explicit`，不会自动制造 inferred；暂定推断的优先级与弱参考路径用合成数据验证。广泛语义推断准确性不属于已验证能力。
- 管理员输入不伪造消息 ID；手动修改有 revision 和 audit。锁定项不会自动覆盖；新近明确要求覆盖旧推断，旧历史不能覆盖更晚明确反馈。
- JSON 事实库的旧写入不会覆盖通信 SQLite。原事实学习/压缩自身的并发缺陷不在本轮重写范围，也不因本轮测试而视为已经修复。

## 人设解析及迁移

正常私聊与统一角色入口使用 `resolve_persona()`：联系人显式指定 > 当前全局 > 内置助手。删除联系人绑定后立即重新继承，全局正文从未复制到联系人记录中。

本轮只读盘点到当前账号 1 条 `reply_ai` 规则（`style-reply`, `match.type=auto`），角色为“夏以昼”，无独立全局设置，没有观察到多规则角色冲突；4 个监听会话都是私聊。本轮没有为这些联系人写入任何绑定。

为避免未经授权改变现有角色，在显式迁移前存在可见兼容态：

1. 唯一旧规则角色作为虚拟全局来源，界面标“继承现有唯一规则人设（待显式迁移）”。联系人显式设置仍然优先。
2. 第一次保存全局必须保持旧唯一角色。保存后记录 `legacy_migration` 审计和原规则清单，再通过后续明确操作改变全局角色。旧规则文件不自动重写；统一解析不再使用其中的旧角色字段。
3. 多个旧规则角色冲突时列出规则下标、名称、匹配条件和角色 ID，拒绝自动全局迁移。未迁移的私聊按实际触发的旧规则保留行为，界面明确标“规则相关”，不会声称始终使用列表中的某一个角色；旧主动入口的首规则行为也显式标为冲突兼容态。
4. 群采用群 ID 自身绑定或全局，不按发言成员换角色，不读取私聊交流偏好。未迁移的群规则角色冲突时使用明确的内置回退并展示错误，必须由管理员核对后配置；当前账号没有这一冲突。
5. 人设删除、空正文、配置损坏使用明确内置回退，不换用其他联系人的角色、不让普通回复因角色引用损坏崩溃。
6. 自动回复、手动打招呼、拍一拍回应、主动跟进均调用同一解析函数和偏好选择器。定时任务保留其原有显式任务人设/定时助手语义；它是任务指令，不迁移为联系人聊天角色，也没有修改既有任务配置。

旧 `/api/bot/persona` 写接口在新后端返回 409 并引导至新管理页，避免旧页面显示设置成功、实际只改了已经不生效的规则字段。旧后端不支持新能力时，现有前端仍调用旧接口。

## 提取、更新和恢复

本版使用无模型的保守规则，从属于当前私聊联系人、发送者匹配、真实入站 type=1 文本中提取明确长期反馈。例如“以后短一点”“以后回复详细一点”“以后不要用表情”。

- 单次要求、短问句、情绪、条件句、引用、系统消息、定时消息、机器人文本和标注虚构内容不产生偏好；“不想说话了”不被写成永久人格。
- 不是任意自然语言理解器。未匹配的表达保持未知，支持管理员补充。不从几条短消息推断敏感身份、心理诊断、财富或依赖程度，也不模仿联系人的人格。
- `learn_live()` 只处理轮询已发现的新消息，首次监听只记 bot 原有位置；不启动历史全库扫描。
- 实时明确反馈先持久化原消息 ID 范围的任务意图，再在事务中更新偏好、证据去重和完成状态。失败/中断保留到管理页，可从原消息库恢复；不保存原聊天正文。不重放已完成 live 批次。
- 历史构建是独立进度，和 bot 回复指针、实时偏好进度相互独立。只读预览 -> 明确创建范围任务 -> 每次执行最多 50 条。偏好、seen、job cursor 和历史 progress 同一个 SQLite 事务提交；中断要么全提交，要么全回滚。
- SQLite `BEGIN IMMEDIATE` 与 `synchronous=FULL`；管理员修改用乐观 revision 防止覆盖。提交边界核对账号代次。新账号看不到旧账号任务，旧代次结果不能写新账号；原账号下的中断历史任务可由管理员显式恢复，重新按现有原账号数据库证据处理。
- 失败没有无限后台重试。每次点击最多执行一批，失败保留原因类别。数据库完全无法写入时，任务意图也可能无法建立，不能保证这一故障下零漏学；后续显式历史构建仍可从独立进度补扫。
- 任务、证据与审计尚无自动清理策略；列表优先展示未完成任务并限制最近 100 条，但磁盘记录保留。部署后应观察增长，再决定保留策略，不在本轮自动清理真实数据。

## 回复上下文与合成示例

组装顺序：通用真实性/当前请求优先 -> 本轮机器人角色及其表达示例 -> 最多 4 项相关交流偏好 -> 当前作用域相关事实、近期对话 -> 当前请求。

旧机器人的消息只是对话背景，不继续充当旧角色指令；角色样例不当作与当前联系人的真实共同经历。角色切换不清空真实事实。移除了普通回复强制“回 1~2 句”的指令。当前明确要详细、逐步或简短时，不把长期长度偏好同时选入本轮。

同一个合成角色“友善、诚实、克制的助手”，当前请求“你觉得我该怎么安排这件事”：

- 合成联系人 A：管理员锁定“简短、直接、少追问”。上下文选择这三项，先给重点，避免强制反问。
- 合成联系人 B：明确表达“详细、温和、先听对方说”。上下文选择这三项，以温和表达适当展开，建议方式作为参考。
- 同样两人若明确要求“请详细列出每一步”，A 的长期“简短”不被选入；两者当前任务都是详细解释。角色相同、事实检索仍按联系人/会话隔离。

这些是上下文组装说明，不是实际模型生成结果，也不证明回复更自然。

## 已有微信语音转写

只读检查发现，所请求联系人的目标语音转写位于现有解密消息库 `packed_info_data`，外层 protobuf 字段 5，内层字段 1=2、字段 2 为 UTF-8 文本。不是 `message_content` 的 voicemsg XML 正文。

`voice_text.from_packed()` 只接受这一已观察到的完整布局；`messages.get_messages()` 附带 `voice_transcript/voice_transcript_source`；媒体读取与主动上下文先复用已有转写，再按旧媒体策略处理缺失。已有转写时，即使 `enable_stt=False`，也不会获取音频或请求 STT。

真实记录只证明这条微信已有转写可读。未听取原始音频核对准确率，未证明其他客户端版本、未完成转写或未来格式均兼容；未知布局保持未读取，不猜测语音内容，也没有开启 STT。

该语音是本次结束交流的意愿，不应作为稳定性格。现有主动跟进调度没有“识别结束交流并硬停止”的状态门，本轮没有修改它的开关、频率或发送条件；提示中的尊重边界不是停止调度的强保证，这仍是需单独处理的风险。

## 管理操作与费用

部署相容后，从原 AI/画像面板的“联系人画像与专属人设”入口进入 `/personalization`：

1. 输入管理员 Token，点击加载；Token 仅保留在内存，全部 `/api/personalization` 数据接口沿用管理员权限校验。
2. 先看旧规则与迁移来源；选择联系人/群稳定 ID，设角色或继承、开关；修改/锁定/删除偏好，查看最近 30 次审计。
3. 输入当前请求，点击“预览脱敏组装”。显示实际角色名称/来源、真正入选的偏好及顺序；称呼等自由文本和角色正文脱敏。不读完整事实/私人聊天，不调用模型、不发送。
4. 选择 1–10 位私聊联系人，每位每批 1–1000 条；点击只读范围预览，查看 ID 范围、条数、提取建议、预计调用 0 次。确认后只创建任务，不自动执行；点击继续，每次最多 50 条，失败可重试，刷新/重启不会自行恢复调用。
5. 暂停自动更新会保留未完成任务；重新允许后可继续。清空偏好不清理原事实、人设与审计。已消费旧证据不因刷新而复活被删除偏好。

真实历史构建本轮未执行。当前规则提取器的模型调用数、费用均为 0；没有隐藏的“智能生成”按钮。未来如需模型语义推断，须另行明确联系人/消息范围、分批大小、调用上限及单价，本版不会因启动/开页自动接入。

页面在 `/api/llm` 返回 `contact_personalization=true` 时才从旧 UI 显示入口；防止新静态文件在旧生产后端下露出不兼容功能。每个写请求携带加载页面时的账号代次；读响应发现账号变化就使旧表单失效，不能将旧表单保存到新账号。
