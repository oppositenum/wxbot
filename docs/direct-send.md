# 直发（底层发送）使用说明

「直发」是在微信进程里直接调用它自己的发送函数（Frida 注入），不再模拟鼠标键盘去搜索联系人、粘贴、点发送。
比界面自动化快（一条约 0.1 秒）、不抢桌面、不受窗口位置影响，还能做界面自动化做不到的事：
撤回、真 @ 提醒、引用回复、直发语音条。

逆向细节和微信升级后怎么重新定位偏移见 [wechat-direct-send-re.md](wechat-direct-send-re.md)。

## 支持范围

| 项目 | 说明 |
| --- | --- |
| 微信版本 | **Linux 4.1.13.29**（主力）和 4.1.8（只有文字/图片/视频/文件/撤回）。按微信主程序的 sha256 识别，版本对不上就自动停用直发、改走界面发送，不会乱调。 |
| 架构 | **arm64**（Apple Silicon、ARM 服务器）。amd64 上没有适配偏移，自动走界面发送。 |
| 依赖 | 镜像里自带 frida 17.23.3、pilk（语音条编码）、ffmpeg、EGL/GLES（4.1.13 发视频生成封面要用）。 |

## 能发什么

| 类型 | 4.1.13 | 说明 |
| --- | --- | --- |
| 文字 | ✅ | 最长 2000 字 |
| 图片 | ✅ | PNG/JPEG/GIF/WEBP，20MB 内；发完会等微信真正上传成功（最多 25 秒）才算发出 |
| 视频 / 文件 | ✅ | 任意文件按文件卡片发 |
| 语音条 | ✅ | 文字转语音或音频文件 → 编成微信 SILK 直发，对方收到的是正常语音条 |
| 撤回 | ✅ | 只能撤自己发的、2 分钟内的；文件传输助手没有撤回 |
| @ 提醒 | ✅ | 群里 @ 指定成员（对方收到「有人@我」）；正文里写「@成员名」也会自动变成真 @ |
| 引用回复 | ✅ | 引用会话里某条消息再回复（appmsg 57，微信自己生成 `<refermsg>`） |

## 怎么开

后台 → 「直发测试」页（`/direct-send`）：

- **发送方式**：`界面自动化` / `直发`。机器人回复、定时消息、`/api/send` 都按这个走，改了立即生效（存 `work/send_mode.json`）。
- **失败回退**：直发「确定没发出」（没连上、没登录、版本不支持等）时自动改走界面发送；结果不确定时绝不回退，避免重复发送。
- 页面上半部分可以手动直发文字/图片/视频/音频、选择 @ 谁、引用哪条、撤回上一条，下方有直发记录。

机器人相关的三个开关（默认全关，只有直发 + 4.1.13 才生效，做不到时照常发文字）：

| 开关 | 作用 |
| --- | --- |
| `group_quote` | 群里回复某人时，第一条引用对方那句话 |
| `group_at` | 群里最近 10 分钟有两人以上在说话时，第一条 @ 要回答的人 |
| `draw_quote` | 画图时，发图前那句「在画了」引用对方要图的消息（微信的引用只能是文字，图片本身带不了引用） |

## 接口

都在后台登录后可用；标了 token 的也接受 `Authorization: Bearer <WXBOT_API_TOKEN>`。

| 方法 | 路径 | 参数 |
| --- | --- | --- |
| GET | `/api/direct/status` | 版本是否适配、是否已附加、是否已登录、撤回/语音/引用/@ 是否可用 |
| GET | `/api/direct/history` | 最近的直发记录 |
| POST | `/api/direct/send` | JSON `{chat, content, name?, at?: [wxid] , quote?: local_id}`；不传 `at` 时正文里的「@成员名」自动变真 @ |
| POST | `/api/direct/send_image` | 表单 `file` + `chat` + `name`；按文件头自动识别图片/视频/音频 |
| POST | `/api/direct/send_tts` (token) | JSON `{chat, text, voice?, name?, send_as?}`，`send_as` = `voice_bar`（语音条）/ `video` / `file` |
| POST | `/api/direct/revoke` (token) | JSON `{chat, local_id?}`，不填 `local_id` = 撤回该会话我最近发的一条 |
| GET/POST | `/api/send_mode` | `{mode: ui|direct, fallback, group_quote, group_at, draw_quote}` |
| POST | `/api/send` (token) | 通用发送队列，额外支持 `at: [wxid]`、`quote: local_id`（引用要直发 + 4.1.13） |

`chat` 用 wxid 或 `xxx@chatroom`；`local_id` 来自 `/api/messages`。curl 示例见 [api-send.md](api-send.md)。

## 结果怎么看

- 「已交给微信发送」= 微信已经收下这个发送任务。文字基本等于发出；图片会再等微信上传结果。
- 发送记录里 `wechat_upload_failed` = 微信里这条图片上传失败（对方看到红色感叹号），见下面「坑」。
- 直发不会在微信界面上留下操作痕迹，但消息在手机和电脑上都正常显示为自己发的。

## 坑（都踩过）

1. **一次媒体上传失败后，之后所有图片/视频/文件都会失败，直到重启微信。** 表现：发图出现红色感叹号、机器人日志提示
   「需要重启微信」。处理：重启微信（容器里 `pkill -x wechat` 后重新拉起，或重启容器），然后在 noVNC 里点「进入微信」。
2. **4.1.13 发视频需要 EGL/GLES 库**，缺了视频必失败并触发第 1 条。镜像已装好；自己改镜像时别删 `libegl1 libgles2 libgl1 libegl-mesa0`。
3. **抓图片密钥只能 hook 软件 AES 的 `set_decrypt_key`（0x8cb8584）**。同时 hook `set_encrypt_key` 会触发第 1 条，代码里已限定。
4. 微信升级后偏移全部失效：直发会按 sha256 自动停用并回退界面发送，等按 [wechat-direct-send-re.md](wechat-direct-send-re.md)
   第 4 节重新定位后再启用。镜像锁定了 4.1.13.29，避免误装新版。
5. 文件传输助手：不能撤回；4.1.13 界面搜索找不到它（界面发送不能发给它，直发可以）。

## 和数据库密钥的关系

直发本身不需要数据库密钥。但「刷新密钥」在 4.1.13 上要靠直发触发微信读库：它会往**自己的文件传输助手**发一条文字、
一条 2 秒语音（只有缺视频相关的库时才再发一段 1 秒视频），这些消息可以删除。
