# 消息处理改进（2026-09-10）

参考 Agent Console 的参与决策、发言记录、发送前复核和上下文窗口设计，参考提交为 `ed686d9910732e47eccc178d8cdba6cae818b7da`。实现沿用 wxbot 的本地 SQLite、账号代次和早期 Linux 搜索发送端，没有安装外部项目或引入它的 Windows SDK、Redis、PostgreSQL。

## 当前流程

微信本地消息库 → 独立后台增量读取 → 原有账号隔离的游标和待回复批次 → 回复决策 → 上下文与模型 → 获取微信界面锁 → 刷新并复核新消息 → 重复内容检查 → 早期发送脚本。

后台读取每 0.35 秒检查一次来源变化；来源没有变化时不重复解密。消息库仍是持久收件箱，原来的游标负责消费。所有 `decrypt.run` 调用共享锁，避免同时替换同一个临时文件。模型与回复处理仍由单个机器人工作线程顺序执行，微信界面仍然串行；这是读取与回复处理的分离，没有启用多个聊天同时调用模型。

## 回复决策

- 单条完整结束语跳过，保留引用、提问、附加信息、多条消息批次的原有行为。
- 最后一条完整文字明确要求“先别回了/不用回复了”等，取消本批回复。
- 按实际发送者判断自己的消息；当前问题之后已有本账号发言，跳过旧问题。
- 普通回复、主动跟进、主动问候使用发送前检查。生成中的 Agent 经同一协调器发送文字或图片时也受当前回复范围约束。
- 发送前出现新的私聊入站消息，取消旧候选回复，将未发送的原问题与新消息合并。群聊只因原发言者的新消息或新的直接提及/引用而更新，其他成员的无关聊天不自动取消原问题。
- 生成期间出现本账号发言，且不能与近期已记录的程序发送内容对应，取消旧回复。系统不能从同一账号的发言中完美证明人工/程序来源，因此采用保守处理。
- 收到停止机器人操作后，尚未进入发送脚本的自动回复会被拦截。

## 重复检查与上下文

复用发送记录中的近期文字内容，覆盖不同任务生成的自动回复、问候、跟进；对相同文本及高度相似的较长文本进行检查。检查范围为最近 30 分钟、至多 40 条已开始发送或已提交/确认的记录；实际上下文中最近的本账号文字也可参与比较。仅改变标点的相同内容会命中；数字、否定词或链接发生变化时不使用近似匹配。

对明确提问、要求重复/解释、引用和媒体请求保留回答，避免把必要的事实回答吞掉。手动发送、转发和定时任务不因这项闲聊重复规则被统一拦截。它是保守的文本检查，不能识别所有同义改写，也没有采用群聊固定发言配额或强行截短答案。

历史保留实际双方角色、群成员身份和引用归属，仍先排除当前批次。最近最多 8 条历史增加 12,000 字符软预算，保留连续的近期片段和最近一条历史。当前新消息批次不截断；很长的最新消息仍可能超过软预算。

## 恢复与诊断

已确认没有进入 UI 发送、但本地快照暂不可核对时，保留生成结果，间隔 5 秒最多尝试 3 次发送前检查，不重新调用模型。恢复仍需绑定原账号和回复上下文。新消息会合并后形成新批次。超过尝试上限保留记录，等待后续新消息或人工处理。

发送脚本已经启动、超时、结果不确定或工具已经部分发送时，不通过“新消息合并”重放旧批次。`submitted` 表示界面已提交，`confirmed` 才表示已有确认；早期发送端继续返回 `submitted`。发送前复核只覆盖进入原脚本之前，无法撤销原脚本运行期间已经开始的搜索/粘贴/回车。

机器人日志记录合并排队、模型与工具、界面锁等待、发送前复核、界面提交的耗时，以及中文跳过/延后原因。发送库中的 `reply_decisions` 记录最近 500 个批次的状态、原因和处理耗时，不新增聊天正文。`GET /api/bot` 的 `message_reader` 字段提供后台读取状态。

## 验证

测试必须按文件分别启动进程：`test_acceptance_preview.py` 安装不可移除的进程级隔离审计钩子，不能与其他测试在同一个发现进程中运行。

新增 `tests/test_reply_policy.py` 的 23 个离线案例覆盖结束语/取消、发言归属、上下文预算、不同任务重复、重复回答例外、生成中改口与人工回复、群聊无关消息、后台读取并行、快照一致性、有限恢复、停止、部分发送与不确定结果不重放、显式转发规则保持。既有发送恢复测试补充了合成的最新消息快照。

全部 15 个 Python 测试文件独立运行，共 361 项检查。测试阻断真实网络、模型和微信发送；只能证明这些控制逻辑，不能据此承诺真实模型永不重复、发送耗时下降多少或解除微信风控。
